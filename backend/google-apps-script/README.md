# PDF 신청 정보 자동 저장

GitHub Pages에는 서버나 비밀 키를 둘 수 없으므로, Google Apps Script가 관리자 권한으로 비공개 스프레드시트에 기록합니다. ChatGPT 계정, Sites, 시간 단위 동기화는 필요 없습니다. 실제 저장 성공 응답을 받은 뒤 브라우저가 PDF를 엽니다.

## 관리자 최초 설정

1. [Apps Script](https://script.google.com/home/start)에서 새 프로젝트를 만들고 `Code.gs` 내용을 붙여 넣습니다.
2. 기존 신청 명단을 계속 사용하려면 프로젝트 설정 → 스크립트 속성에 `SPREADSHEET_ID`를 추가합니다. 값에는 기존 비공개 신청 명단의 ID만 넣습니다. 이 속성을 생략하면 `setup`이 새 비공개 명단을 만듭니다.
3. `setup` 함수를 한 번 실행하고 요청된 Google 권한을 승인합니다. 헤더가 있는 명단은 덮어쓰지 않습니다. 1년이 지난 신청을 매일 정리하는 트리거도 만듭니다.
4. 배포 → 새 배포 → 웹 앱. 실행 사용자: **나**, 액세스 권한: **모든 사용자**. 배포 후 `/exec`로 끝나는 웹 앱 URL을 복사합니다. `/dev` 주소는 사용하지 않습니다. Workspace 정책이 익명 웹 앱을 막는 경우 관리자의 정책 변경이 필요합니다.
5. 저장소 루트에서 `python tools/connect_registration.py 'https://script.google.com/macros/s/실제배포ID/exec'`를 실행하고 변경된 `webbook/config.js`를 GitHub에 반영합니다.
6. 로그아웃한 브라우저에서 이름·소속·이메일·동의를 입력합니다. 스프레드시트에 정확히 한 행이 생기고 PDF가 열리는지 확인합니다. 같은 요청의 재시도는 중복 기록하지 않습니다. 정보는 공개 페이지에 표시되지 않습니다.

웹 앱은 `text/plain` POST JSON을 받고 JSON `{ok:true}`를 응답합니다. Google의 ContentService 리다이렉트를 따릅니다. 프런트엔드는 응답을 읽지 못하거나 오류가 있으면 성공으로 표시하지 않습니다. 배포 후 실제 브라우저에서 전체 흐름을 확인해야 합니다.

키나 Google 계정 토큰은 저장소에 넣지 않습니다. 공개되는 웹 앱 URL은 비밀 키가 아닙니다. 입력값 길이 제한·허니팟·이메일별/분당 요청 제한을 적용했습니다. Apps Script의 무료 할당량을 초과하면 신청은 오류로 안내됩니다.

## 연결 전 동작

`webbook/config.js`의 `registrationEndpoint`가 빈 문자열이면 개인정보를 묻지 않고 PDF를 바로 엽니다. 연결되지 않은 폼에서 정보를 수집했다고 표시하지 않습니다. 본문·검색·기록·공유·PDF는 GitHub Pages만으로 작동합니다.

## 이전 명단

기존 명단을 지정하면 전에 만들어 둔 ChatGPT의 시간 단위 동기화 자동화는 기존 Sites 신청만 처리합니다. 새 웹북 신청은 Apps Script가 같은 시트에 직접 저장하므로 자동화와 무관합니다. 기존 ChatGPT 웹북은 별도 요청 없이 폐쇄하거나 접근 범위를 바꾸지 않습니다.

## 소감 기능 추가 또는 재배포

[코드 복사와 연결 안내](https://questionschool.net/webbook/setup-feedback.html)를 엽니다. 기존 `Code.gs`를 최신 전체 코드로 교체하고 `setup`을 한 번 실행합니다. 이어 **배포 → 배포 관리 → 기존 웹 앱 → 연필 → 새 버전 → 배포**를 선택합니다. 주소가 유지되므로 `config.js`를 다시 바꿀 필요가 없습니다.

`웹북 소감` 탭에는 소감 ID / 작성 일시 / 별칭 / 소감 / 공개 여부 / 동의 버전을 저장합니다. `public` 글만 `GET?action=feedback`의 공개 목록에 포함됩니다. `private` 글은 시트 관리자만 볼 수 있고, 공개 응답에는 이름·본문 모두 포함되지 않습니다. 웹북은 별칭과 본문을 HTML로 해석하지 않고 텍스트로 표시합니다.

기존 PDF 신청 저장과 1년 보관 후 자동 정리는 유지됩니다. 소감도 1년 후 정리합니다. 관리자가 글을 삭제하려면 해당 소감 ID의 시트 행만 삭제합니다. 공개 여부를 바꾸려면 해당 행의 공개 여부를 `private` 또는 `public`으로 바꿉니다.

웹북은 서버 응답에서 소감 기능을 확인한 뒤에만 입력창을 표시합니다. 이전 PDF 전용 배포가 동작하는 동안은 연결되지 않은 소감 입력창이 노출되지 않습니다.

## 자체 방문 집계

`/webbook/setup-visitors.html`에서 전체 코드를 복사해 기존 Apps Script에 붙여 넣고 기존 웹 앱을 새 버전으로 배포합니다. 주소와 SPREADSHEET_ID는 유지합니다. setup 재실행은 필요 없습니다. 첫 방문에 관리자 시트의 `웹북 방문 통계` 탭이 생성됩니다. 누적 수는 한국 시간 기준 브라우저별 일일 방문 수의 합계이며, 전체 기간의 고유 인원 수는 아닙니다. 원시 식별자·IP·신청 정보는 저장하지 않습니다. 날짜별 salted hash로 당일 중복을 막고 다음 날 첫 방문에 이전 해시 행을 삭제하면서 누적 집계는 유지합니다. 별도 예약 자동화는 만들지 않습니다.

`GET?action=visitorStats`는 공개된 숫자만 반환하고 `POST {action:"visit",visitorId:"브라우저 UUID"}`는 하루 한 번 기록합니다. 클라이언트는 서버 기능을 확인한 뒤에만 위젯을 표시합니다. 브라우저 저장소를 사용할 수 없으면 카운트를 올리지 않고 숫자만 읽습니다. 기존 웹북의 과거 방문 수는 소급 복원하지 않습니다.

PDF 다운로드는 실제 파일 수신 완료가 아닌 신청 성공 건수로 집계하며 직접 PDF URL 접속은 포함하지 않습니다. 설정 검증용 ID는 제외하고 개인 신청 행의 1년 보관기간이 지나도 익명 합계 PDF_DOWNLOAD_TOTAL은 유지합니다.\n
화면 표시값에는 운영자가 지정한 시작값(누적 1000·일일 100·PDF 100)을 더합니다. 서버에는 실제 집계만 보존하며 화면에는 숫자만 표시합니다. 일일 표시값은 한국 시간 자정마다 100부터 다시 시작합니다.
